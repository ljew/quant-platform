# QMT 看门狗 · Windows 端部署与运维

> 解决一个很具体的问题：**策略在 QMT 沙箱里跑，卡死了外面看不见。**
> 它不能写文件、不能联网、不能推告警。客户端崩了、策略没被加载、handlebar 不再触发，
> 你只有在第二天对账时才发现"昨天根本没下单"。
> 看门狗跑在 QMT 外面，替它盯着、替它喊人。

- 代码：`qmt/watchdog/`（`watchdog.py` 主程序、`selftest.py` 自检、`install.bat` / `uninstall.bat`）
- 依赖：**无第三方库**，Python 3.8+ 标准库即可（Windows 机器上不用 pip 装任何东西）
- 自检：`cd qmt/watchdog && python3 selftest.py`（53 项，Mac 上就能跑，不需要 Windows）

---

## 1. 三级心跳

| 级别 | 判据 | 说明 | 失败意味着 |
|---|---|---|---|
| **L1 进程** | QMT 客户端进程在不在 | `tasklist` 按配置里的进程名查 | 客户端崩了 / 被关了 / 没开机 |
| **L2 活性** | 日志里最近的 `[hb]` 距现在 < 35 分钟 | 策略每 15 分钟打一行心跳 | handlebar 不再触发、策略没被加载、日志路径配错 |
| **L3 结果** | 15:05 之后有 `[done]`；无 `[alert]` | 当日执行完成标记 | 今天这笔调仓可能没跑成，或跑出异常 |

**为什么 L2 靠日志而不是靠端口**：QMT 内置策略没有对外端口，且沙箱禁止它写状态到外面。
`print` 落到客户端日志，是外部唯一能看见的活性证据 —— 策略侧已加 `heartbeat()`
（每 15 分钟一行 `[hb] YYYY-MM-DD HH:MM alive`，放在 handlebar 最前面，当天跑完也继续打）。

## 2. 处置规则

| 情况 | 动作 | 理由 |
|---|---|---|
| L1 连续失败 3 次 | 杀进程 → 重启客户端 → 冷却 10 分钟 → 复查 | 防抖：一次抖动（启动中、卡顿）不该触发重启 |
| 重启后复查仍在 | 记一次失败；累计 3 次后告警升级为【人工介入】 | 重启解决不了的问题，别一直重启 |
| 当日重启满 3 次 | 不再重启，只告警 | 防止重启风暴把账户搞乱 |
| L2 心跳过期 | **只告警，不重启** | 多数是行情延迟 / 无候选 / 日志路径错，重启没用还添乱 |
| 找不到日志文件 | 告警「心跳源缺失」 | 宁可明说"我看不见"，也不能假装一切正常 |
| L3 收盘无 `[done]` | 告警「当日未执行」 | 这是真正要人去看委托列表的信号 |
| 进程恢复 | 发一条「已恢复」 | 否则你只知道出过事，不知道好了没 |

**冷却期和去重窗口都落盘**（`watchdog_state.json`）：看门狗自己也可能被重启，状态不能只放内存。
重启额度、告警去重**按天重置**。

## 3. 部署（按顺序做）

### 第 1 步 · Windows 机器上准备 Python
- 需要 Python 3.8 或更高。没有就装 [python.org](https://www.python.org/downloads/windows/) 的 Windows installer（装时勾选 *Add python.exe to PATH*）。
- 装完开一个 **命令提示符**，执行 `where python`，把输出的完整路径记下来（后面填进 `install.bat`）。

### 第 2 步 · 把目录拷过去
把整个 `qmt/watchdog/` 目录拷到 Windows 机器，例如 `D:\qmt-watchdog\`。
目录里应有：`watchdog.py`、`selftest.py`、`calendar.json`、`watchdog_config.example.json`、`install.bat`、`uninstall.bat`。

### 第 3 步 · 先跑一次自检（确认代码本身没问题）
```
cd D:\qmt-watchdog
python selftest.py
```
应看到 `通过 53 · 失败 0`。这一步不碰真实进程，放心跑。

### 第 4 步 · 生成配置
```
copy watchdog_config.example.json watchdog_config.json
notepad watchdog_config.json
```
**必填两项**：
1. `qmt.exe_path` —— QMT 客户端主程序的完整路径。
   找法：桌面 QMT 图标上点右键 → 属性 → 「目标」那一栏就是。
2. `qmt.process_names` —— 打开任务管理器，启动 QMT，看「详细信息」里新增的进程名
   （常见 `XtItClient.exe`，不同券商不一样），填进去。

可选：`alert.webhook`（见第 6 步）。

### 第 5 步 · 定位日志文件（最关键的一步，别跳）
```
python watchdog.py --probe-logs
```
它会打印：进程在不在、日历载入情况、**候选日志路径命中了几个**。

- 命中了 → 把没命中的路径从配置 `logs.globs` 里删掉，只留命中的。
- 一个都没命中 → 在 QMT 策略里随便 `print("FINDME-123")` 跑一次，
  然后用资源管理器搜索 `FINDME-123` 出现在哪个文件里，把那个文件的路径（支持 `*` 通配）填进 `logs.globs`。

**这一步没做对，L2/L3 全部失效**，看门狗只会告诉你"心跳源缺失"。

### 第 6 步 · 装开机自启
用记事本打开 `install.bat`，把第 12 行的 `PYTHON_EXE` 改成第 1 步记下的路径，保存。
然后 **右键 install.bat → 以管理员身份运行**。

装完验证三件事：
1. 任务管理器里能看到 `pythonw.exe` 常驻；
2. 目录下 `watchdog.log` 有内容；
3. `python watchdog.py --status` 能看到三级心跳的结果。

### 第 7 步 · 机器设置（别让 Windows 自己把事搞砸）
- 电源：设置 → 电源 → 「从不」睡眠/休眠。
- Windows 更新：把「自动重启」关掉，或把活跃小时设成 08:00–16:00。
- QMT 客户端：勾选**记住账号密码 + 自动登录**（否则重启后卡在登录页，看门狗白重启）。

## 4. 上线前必须在真机确认的四件事 ★

这四条 mock 和自检都模拟不了，**不确认就上实盘等于赌**。

| # | 要确认什么 | 怎么确认 | 不确认的后果 |
|---|---|---|---|
| 1 | **重启后 QMT 会不会自动登录并自动运行策略** | 手工杀掉 QMT 进程再启动，看策略是否自己跑起来 | 看门狗重启了客户端，但策略没被加载 → 照样不下单，而你以为没事 |
| 2 | `print` 是否真落到配置里的日志文件 | 策略里打一行带时间戳的标记，去文件里搜 | L2/L3 全是瞎的 |
| 3 | `handlebar` 的触发频率 | 观察心跳行间隔是否 ≈15 分钟 | 若一天只触发一次，心跳间隔要改大，否则天天误报 |
| 4 | 杀进程重启会不会影响已挂委托 | 挂一笔不成交的委托 → 重启 → 看柜台是否还在 | 重复下单（已由 `sync_pending_from_broker` 兜底，但要实测） |

**关于第 1 条的诚实说法**：如果券商版本的 QMT 不支持"重启后自动运行策略"，
看门狗的价值就降级为 **及时发现 + 通知人工**，而不是"自动恢复"。
这不是缺陷，是沙箱规则的边界 —— 能重启进程，替不了你点那个"运行"按钮。

## 5. 关于防超单的一个坑（已修）

`PENDING` 是内存字典，客户端重启就清空 → `has_open_order` 恒为 False → **防超单失效**。
而看门狗会自动重启客户端，等于自己引入了这个风险。

已修：`sync_pending_from_broker()` 在每次下单前用柜台的真实委托重建 `PENDING`
（只认 `userOrderId` 前缀 `fm_`，终态剔除，别家策略的单不碰），60 秒节流。
自检场景 18 专门验证这条。

## 6. 告警配置

`watchdog_config.json` 里 `alert` 段：

| 字段 | 说明 |
|---|---|
| `channel` | `wecom`（企业微信机器人）/ `feishu`（飞书）/ `log`（只写本地日志） |
| `webhook` | 机器人地址；留空则只写 `watchdog.log`。也可设环境变量 `WATCHDOG_WEBHOOK` |
| `dedup_sec` | 同类告警最小间隔，默认 1800 秒（半小时），防止刷屏 |
| `escalate_after` | 重启失败几次后标题加【人工介入】，默认 3 |

企业微信机器人地址：群里右键 → 添加群机器人 → 复制 Webhook 地址。
（平台侧 `backend/app/services/mailer.py` 走的是邮件 + 飞书，与这条链路无关。）

告警样例：
```
QMT 看门狗：当日未执行
机器：DESKTOP-XXXX
时间：2026-11-02 15:10:00
收盘前未见到 [done]，今天这笔调仓可能没跑成
请人工核对 QMT 委托列表
```

## 7. 运维手册

```
python watchdog.py --status        # 看当前三级心跳（排障第一件事）
python watchdog.py --once          # 只跑一轮就退出（计划任务保活模式用）
python watchdog.py --once --dry-run # 演练：只说打算做什么，不真重启不真发
python watchdog.py --probe-logs    # 重新探测日志路径
python watchdog.py                 # 常驻循环（默认，install.bat 用的就是这个）
```

| 文件 | 用途 |
|---|---|
| `watchdog.log` | 每轮检查结果、所有告警原文。**出问题先看它** |
| `watchdog_state.json` | 连续失败计数、当日重启次数、告警去重时间戳。删掉即重置 |
| `watchdog.lock` | 单实例锁（防止计划任务堆出多个看门狗）。进程异常退出后会自动接管 |

**常见问题**

| 现象 | 原因 / 处理 |
|---|---|
| 一直报「心跳源缺失」 | 日志路径没配对，重跑 `--probe-logs` |
| 工作日正常，节假日也报警 | `calendar.json` 没载入（日志会写"日历缺失"）。重跑 `scripts/export_calendar.py` |
| 明年节假日误报 | 源日历只到当年，跨年前重跑导出脚本（脚本会主动警告缺失年份） |
| 一直重启一直失败 | 重启额度用完会自动停手并升级告警，去真机看 QMT 为什么起不来 |
| 想临时停掉 | 任务管理器结束 `pythonw.exe`，或跑 `uninstall.bat` |

## 8. 已知边界

1. **看门狗不参与决策**，也不碰平台。它只看得见 Windows 本机；平台侧的对账仍靠人工导 CSV（见 `GO-LIVE-PLAN.md`）。
2. **它不能代替人工核对委托**。L3 报"当日未执行"只是提醒，最终以 QMT 委托列表为准。
3. **重启额度是硬上限**（默认每天 3 次）。如果你想要更激进的恢复策略，改配置，但想清楚：
   自动重启本身就是在无人值守时操作账户，宁可保守。
4. **QMT 沙箱可能继续收紧**。哪天连客户端日志都不写了，L2/L3 会一起失效 ——
   那时只剩 L1 进程级监控。这也是为什么平台侧的对账不能省。
