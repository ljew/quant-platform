## 填写规则（生成时必须遵守，不随报告输出）

### R1 · 时区、交易日与每日运行
- 全文统一**北京时间（UTC+8）**，生成时点在报告头写全。
- 美股必须写「美东 MM-DD 收盘 / 北京时间 MM-DD 凌晨」，**禁止只写一个日期**。
  日内跨夜最容易把「美东周四暴跌」错记成「周五暴跌」，本次已实际踩到。
- 自动化**每日运行（含周末）**。每次先判定 `是否交易日`：
  - **交易日**：按本时段正常取数。
  - **非交易日（周末/节假日）**：报告头标注「休市」+ 原因 + 下一交易日；第 2 节引用**上一交易日**收盘数据并逐项标日期，第 3/4 节改为「上一交易日回顾 + 休市期间消息面」，第 5 节观察点指向下一交易日，第 8 节以休市期间资讯为主。
    **严禁虚构当日行情、盘中快照、半日/全天成交额**；本时段确无新增行情要明写「本时段无新增行情」，不得用旧数据冒充新数据。
- 周一早间版覆盖窗口 = 上周五 A 股收盘 → 周一开前，含周末消息面与周五美股。周六/周日各版覆盖窗口 = 周五 A 股收盘 → 该版生成时点。

### R2 · 字段三要素（硬规则）
每个数字必须同时给出：**数据对应日期 + 口径 + 数据源标签**，三者缺一不进结论。
- 利率类尤其要写明口径：中债收益率曲线 10Y / 活跃券 260016 / 银行间收盘 / 美债 10Y，**不同口径不可混用比较**。
- 涨跌幅写清「相对上一交易日收盘」还是「相对结算价」（期货常用结算价，易差 1–2 个 tick）。
- 「-2.96%」这类**相对变动百分比**与「-2BP」不可混写，看到先换算再引用。

### R3 · 溯源标签（字段级，不写整篇一个标签）
| 标签 | 含义 |
|---|---|
| `[通达信✓]` | tdx-connector 实时/收盘快照 |
| `[tushare✓]` | Tushare pro API（收盘价/估值/指数日线） |
| `[neodata✓]` | 国泰海通 neodata-financial-search |
| `[腾讯✓]` | 腾讯 westock-data CLI |
| `[中债✓]` | 中国债券信息网日评（收益率曲线、公开市场） |
| `[公开媒体✓ 来源·日期]` | 财经媒体，必须带**来源名 + 发布时间**，机构观点必须带 publishTime |
| `[待补⚠]` | 未取到，**严禁估算或编造** |
| `[源冲突⚠]` | 多源不一致，必须登记到第 6 节并说明采信理由 |

### R4 · 源校验门（三源交叉）
- 同一字段两源及以上一致 → 并列标签，核心数字标「✅多源一致」。
- 仅单源 → 标该源 + 注「其他源未覆盖」。
- 多源冲突 → **不自行拍板**：第 6 节登记各源数值，按「有无完整时点标注 / 有无交叉印证 / 来源层级」给采信理由，正文用采信值并挂 `[源冲突⚠]`。
- 能做的跨市场换算校验要做（例：COMEX 黄金 USD/oz ÷ 31.1035 × USD/CNY ≈ 沪金 元/克），这是最便宜的假数据探测器。
- 涨跌家数按**交易所口径**相加（沪 + 深 + 北），**不得把创业板/科创板再加一遍**（属深/沪子集，重复计算）。

### R5 · 内容边界（重要）
- 本报告是**信息收集与事实整理**，产出「状态判定 + 可验证的观察点/触发条件 + 资讯简述」。
- **不产出涨跌方向预测、不产出买卖建议；全篇不设裁决区、不设签字栏，不做方向裁决。**
  这与 `a-share-three-source-report` methodology §0「AI 不做最终裁决」一致。
- 方向性判断属发现类（F 通道），归 **A股研究团队**；验证类结论走衡析的假设卡流程。
  本报告不替代其中任何一条，也不得用资讯综述冒充研究结论。
- 引用机构观点必须是**原文可追溯**的公开表述，带来源与日期；不得概括成无名「机构认为」。

### R6 · A 股配色、格式与去重
🔴 涨 / 🟢 跌。表格优先，正文每段不超过 3 行。所有百分比保留两位小数，收益率用 BP 时标 BP。

**去重规则（硬）—— 同一事实只允许出现一次，重复即删：**

| 重复来源 | 处理 |
|---|---|
| 「核心读数 KPI 卡」与第 2 节品种全景 | **不设独立 KPI 模块**；关键数字只在第 1 节给结论、第 2 节给明细 |
| 第 1 节速览与第 2 节表格 | 速览写结论 + 1 个最异常读数，明细与计算过程留第 2 节 |
| 第 4 节状态判定与第 1/2 节 | 只写「五项读数同向 + 一句状态判定」，不重列数字表 |
| 第 6 节源校验与第 7 节缺失清单 | 第 6 节只给计数，明细留第 7 节 |
| 第 8 节资讯简述与第 2/3 节 | **只写事件，不堆数字**；需数值时写「见第 X 节」 |
| 第 8 节「对应表」与第 1 节时序提示 | 同一对应关系只登记一次，另一处写「见速览时序提示」 |
| 章节规则声明与表后重复免责 | 规则只声明一次，表后不复述；免责统一放第 10 节 |

**HTML 版式**：section 内边距 ≤12px、表格单元格内边距 ≤4px、正文 13px / 行高 1.5、
section 间距 ≤9px；不设 KPI 卡片区；自包含、离线可渲染、浅色主题。

**交付与入库（生成后必做）**：`.md` 与 `.html` 写完后执行

```
python3 /Users/happyljew/quant-platform/backend/scripts/ingest_market_report.py --file <生成的 .md 绝对路径>
```

脚本按 `YYYYMMDD_时段` 幂等写入 `market_reports` 表并重建静态索引；返回 `ok:true` 才算交付完成。
入库失败须在完成摘要中写明，不得静默略过。

| **午间版** | **每日** 12:00 | 上午盘 + 早间版之后的增量 | 1/2(A股盘中)/4/5/**8** | **12–20 条** | 3 只写增量，债券商品只写变动 |
| **收盘版** | **每日** 15:30 | 全天 A 股收盘 + 当日亚太 | 1/2/4/5/6/**8** | **16–26 条** | 3 简写 |
| **晚间版** | **每日** 21:00 | 收盘复盘 + 欧美盘前/开盘 + 消息面 | 1/2/3/5/6/7/**8** | **14–24 条** | 4 只留结论性状态 |

> 每份报告必须能**独立读懂**，不得写「见早间版」。增量版也要重列核心数字。
> 周末/节假日四个时段照常出，但一律按**休市版**处理。休市版之间允许核心数字重复，
> **第 8 节资讯简述是主要增量来源**，须重新检索，不得照抄上一时段的资讯列表。

### 8.5 反注水规则（与配额同等硬）

- 一个事件**无论多少家媒体报道只算 1 条**，来源列全、合并叙述。
- **≥70% 的条目必须是不同事件**；同一主体的多条公告可合并为 1 条。
- 同一事实的正反两面不得拆成两条（如「涨 3%」与「涨幅收窄」）。
- 允许**快讯级**条目：一句话、无解读即可，不必每条都写影响分析。
- 纯行情数字（涨跌幅、成交额）不算资讯，除非本身构成事件（历史新高、熔断、涨跌停极值、成交额破纪录）。
- 配额不足时**如实写**「本时段新增 X 条，低于下限，原因：{{休市 / 无重大事件}}」，
  禁止用下列方式凑数：换措辞改写、拆分公司公告、旧闻标新、把行情复述当资讯、把同一事件分行业写多遍。

## 10. 边界与免责
