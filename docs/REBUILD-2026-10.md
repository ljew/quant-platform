# 量化平台效果诊断与重构方案

> 版本 v1.0（待老刘拍板）· 2026-10-08
> 范围：`quant-platform`（主干）+ `iching-quant`（易经实验）+ `Str00-03`（聚宽实盘策略）三套资产的诊断与重构路径
> 性质：本文档仅为方案，**未改动任何生产代码**，等老刘确认后执行

---

## 摘要：问题不在策略，在评估链断了

老刘的直觉「效果很一般」经代码审计 + 数据库实测确认成立，但根因不是市场环境、不是策略逻辑，而是**评估工具本身在骗人**。

一句话概括：**你过去几个月依据平台输出的所有"策略表现"记录，都建立在三个未修复的 bug 之上**——

1. 风控判定（MA 破位减仓/清仓）因复权口径混用而**从未真正触发过**
2. 因子评级函数丢失符号，把**负 IC 因子判为"可用"**
3. 成本与基准口径双轨不一致，**乐观偏差系统性偏高**

在这三点修复前，任何参数优化都是在错误地基上叠加。真实有效 alpha 的现状是：**分散化组合的超额收益 ≈ 0 或为负**。

## 第一部分：审计证据（实测数据，非推断）

### 1.1 致命 Bug #1 —— 风控体系静默失效

**位置**：`backend/app/services/xq/runner.py:113-127`

```python
ma10 = p.df.groupby("symbol", sort=False)["c_hfq"].transform(
    lambda s: s.rolling(10).mean())          # ← 后复权价
ma20 = ...同上...
close = float(latest.loc[sym, "close"])      # ← 未复权价
action, reason = xq_engine.judge(
    sym, streak, reso, today_strategies, close, m10, m20, rules,
)                                             # ← 二者直接比较
```

`c_hfq = close * adj_factor`（见 `xq/data.py:120`）。而 `adj_factor_daily` 实测：

| 指标 | 值 |
|---|---|
| min | 1.00 |
| avg | 10.08 |
| max | 10055.64 |

导致 `ma10 / close` 比值系统性偏离 1.0。**全库实测分布**（`signal_actions` 共 139,211 行）：

| ma10/close 比值区间 | 行数 | 占比 |
|---|---|---|
| > 3 | 54,809 | 39.4% |
| 1.5 ~ 3 | 34,151 | 24.6% |
| 0.9 ~ 1.5（正常） | 45,014 | 32.4% |
| < 0.9 | 5,159 | 3.7% |

**64% 的信号行口径错位。** 极端样本：

| 标的 | date | close | ma10 | 比值 | 判定 |
|---|---|---|---|---|---|
| sz300115 | 2026-09-30 | 22.48 | 292.34 | 13.0× | NEW |
| sz002317 | 2026-09-30 | 24.03 | 279.87 | 11.7× | NEW |
| sh600550 | 2026-09-30 | 10.22 | 80.18 | 7.8× | NEW |
| sz002416 | 2026-09-30 | 8.98 | 33.68 | 3.8× | NEW |

**后果**：`xq/engine.py:135-142` 的整套 MA 破位风控——

```python
if ma_ok and ma20 is not None and close is not None and close < ma20:
    return "SELL", f"跌破 MA20（{close:.2f} < {ma20:.2f}）..."
if ma_ok and ma10 is not None and close is not None and close < ma10:
    return "WATCH"/"REDUCE", ...
```

——逻辑上一条都没正确触发过（因为错位方向导致 close 永远"远低于" MA）。风控被 streak 门槛挡在前面，UI 与报表均无异常，**属于静默失效**。

**注意**：`xq/portfolio.py:106,124,155` 的成交价统一用未复权 `open`/`close`，自洽无问题。**错位仅此一处**，修复面很小。

### 1.2 致命 Bug #2 —— 因子评级丢失方向

**位置**：`backend/app/services/factor_mining.py:554-562`

```python
luck_bar = math.sqrt(2 * math.log(max(n_tested, 2)))
t_excellent = max(2.0, luck_bar + 0.3)
t_usable = max(1.5, luck_bar - 0.3)
if (abs(t_stat) >= t_excellent and abs(ic_mean) > 0.02 and mono_score >= 0.6
        and abs(corr_table.get("max_abs_corr", 0)) < 0.8):
    rating = "优秀"
elif abs(t_stat) >= t_usable and abs(ic_mean) > 0.01:
    rating = "可用"        # ← abs() 抹掉符号
```

`abs()` 用了两次，评级函数**无法区分正负 IC**。

**实测 37 个已挖因子**：

| 指标 | 数量 |
|---|---|
| 正 IC (> 0.02) | **8** |
| 负 IC (< -0.02) | **26** |
| 标为「可用/优秀」但 IC 为负 | **7** |
| t_stat ≥ 2 的因子 | **1**（红利低波 ic=0.0830, t=2.939） |

典型错误：`GP-1·可用  roc(c_r, 40)  ic=-0.0599  t=-1.629` —— 一个反向信号被标为"可用"，按它建仓即做反。

`factor_registry` 表 `status='enabled'` 的仅 1 条，亦由该函数选出。**自动研究闭环的入口是歪的。**

### 1.3 GP 挖矿收敛退化

`factor_gp.py:459-540` 实测三代输出（`factor_mine_results` 表 expr 字段）：

```
GP-1  roc(c_t, 6)     ic=-0.038      GP-1  roc(c_r, 40)   ic=-0.060
GP-2  roc(c_v, 6)     ic=-0.038      GP-2  roc(c_v, 40)   ic=-0.060
GP-3  roc(c_v, 6)     ic=-0.038      GP-3  roc(c_r, 6)    ic=-0.038
```

全部为单变量 ROC 的一阶变体，**未产出任何交互项**。三层叠加原因：

1. `factor_gp.py:466` fitness 在全样本 `[start,end]` 上评估，种群进化与选择同段数据 → 结构性过拟合
2. `auto_research.py` 复杂度上限 ≤4，等于禁止 GP 产出复杂结构
3. `luck_bar` 的 `n_tested` 仅取本次 run 候选数（`factor_gp.py:521` 传 `len(seen)`），**未累计跨 run 检验数** → 门槛被系统性低估

**判断：GP 当前为负价值** —— 消耗算力、产出 70% 负 IC、污染注册表。

### 1.5 Sharpe 未减无风险利率

`backtest_engine.py:382`：`sharpe = (m / std) * math.sqrt(252.0)`，无风险利率隐含为 0。A 股 rf ≈ 2-3%，夏普系统性虚高约 0.03-0.05。影响面小但应修。

| 趋势/动量突破 | dual_ma, ma_cross, ma_alignment, momentum, turtle, turtle_classic, macd_boll | 1 |

### 1.8 iching-quant 三套实验全阴性

| 实验 | 结论 | 关键数字 |
|---|---|---|
| expA 正交化增量检验 | 卦象残差 IC **翻负** | 卦 IC=0.0565；6 因子线性 IC=0.0856；正交化后残差 **IC=-0.0062, t=-12.91** |
| expB 语义接地 | 5 维度**全部不显著** | ρ -0.18~+0.08，置换 p 0.26~0.93，FDR 0/5；对照「阳爻个数」ρ 达 -0.38~-0.41 |
| disagreement_test | **阴性** | `vs_absret` rho=-0.076，分年符号翻转（5 负/1 正），`significant=false` |

`src/gua_semantics.json` 的 `_meta` 字段自述 `source = LLM（阿策）依据卦辞爻辞+上下卦取象` —— **无数据依据**。

**唯一成立的发现**：格雷码邻域假设（相邻卦收益差小 35%，t=-7.65）—— 状态空间有数学结构，**但结构 ≠ alpha**。

### 1.9 Str00-03 过拟合痕迹

## 第二部分：重构路线（分三阶段，严格顺序）

### 设计原则

1. **先止损，再建设** —— 修 bug 优先于调策略
2. **做减法优先于做加法** —— 砍掉无效面比新增功能更有价值
3. **每阶段独立可验证、独立提交** —— 随时可停
4. **测试先行** —— 每个 bug 对应一条回归测试，防止复发

### 阶段一：可信度地基（M1，1-2 天）

**目标：让平台数字可信。这一阶段不产生 alpha，但让后续所有工作有地基。**

| # | 改动 | 文件:行 | 说明 |
|---|---|---|---|
| M1-1 | **统一复权口径** | `xq/runner.py:113-127` | `close` 改取 `c_hfq`（与 MA 同口径）；或在 data 层加 `close_hfq` 别名。**推荐前者**，改动最小 |
| M1-2 | **评级函数加方向** | `factor_mining.py:557-562` | 引入 `direction` 字段（+1/-1），`ic_mean * direction > 0` 才算正向；负 IC 标为「反向可用」并**禁止自动进生产** |
| M1-3 | **成本口径统一** | `backtest_engine.py:235` | 默认改 `slippage=0.0001`，**加印花税万5（卖出）**；`min_commission=5` 已有；与 `xq/portfolio.py:37-58` 对齐 |
| M1-4 | **基准强制校验** | `routers/strategy.py` | 无 `benchmark_symbol` 的回测**拒绝保存**或显式标 `benchmark_missing=True`，禁止 `excess=0` 冒充真实零 |

### 阶段三：重建研究方法（M3，1-2 周）

**目标：这一阶段才真正产生 alpha。前两步是止损。**

| # | 动作 | 说明 |
|---|---|---|
| M3-1 | **样本外框架先行** | 所有因子强制 IS/OOS 切分（2015-2021 训练 / 2022-2026 检验）。**OOS 不过关者禁止进 `factor_registry`** |
| M3-2 | **IC 截面周频化** | 从月度 31 个截面提到周频 200+ 个。样本量翻 4 倍，t 检验才有约束力 |
| M3-3 | **walk-forward 滚动验证** | 替代单次切分。A 股 regime 切换频繁，2019 与 2024 完全两种市场 |
| M3-4 | **正交化进主流程** | iching-quant 的正交化方法（对基准因子残差化）**应用在因子挖掘主流程**，挖增量 alpha 而非重复 alpha |
| M3-5 | **少而正交** | 目标 3-5 个低相关因子，而非 20 个。现有 14 个基础因子中动量/反转/低波/规模本身高度相关 |
| M3-6 | **多重检验正式校正** | 累计 `n_tested`（跨 run）→ Bonferroni / deflated Sharpe / PBO 三选一 |
| M3-7 | **成本敏感性分析** | 每条策略附「成本翻倍后收益」曲线，筛掉只在低摩擦下成立 marginal alpha |
| M3-8 | **组合层优化** | 从等权改为风险平价/约束优化（已有 TODO：多重检验、组合层优化、参数置信区间） |

**验收标准**（这几条是硬门槛，不达标不出生产）：

- [ ] 至少 1 个因子 OOS IC ≥ 0.03 且 OOS t ≥ 2.0
- [ ] 组合 OOS 超额收益 > 0，且 IR ≥ 0.3
- [ ] 成本翻倍后超额仍 > 0
- [ ] 全部结论可被 `pytest` 回归测试复现

## 第四部分：需要老刘拍板的问题

## B2 修复记录：IC 截面密度（月频 → 周频）

### 问题

截面抽样 `i % step == 0`，原 `DEFAULT_STEP = 20`（月频）。实测截面数：

| 区间 | 原 step=20 | 新 step=5 | 提升 |
|---|---|---|---|
| 3 年 | 36 个 | **145 个** | 4.0× |
| 5 年 | 60 个 | **242 个** | 4.0× |
| 7 年 | 85 个 | **340 个** | 4.0× |

t 检验自由度 = 截面数 − 1，**85 个截面约束极松** —— 这是 M1-2 审计中
「IC=0.038、t=1.55 也能判可用」的**检验功效不足**那一半原因
（另一半是评级丢方向，已由 `has_pos` 修复）。

### 关键设计：step 与 forward 解耦

```python
DEFAULT_STEP = 5      # ← 改：20（月频）→ 5（周频），只影响采样密度
DEFAULT_FORWARD = 20  # ← 不变：前瞻期仍是 20 个交易日
```

若把 forward 也改成 5，因子含义会从「预测未来一个月收益」变成「预测一周收益」，
**历史 IC 与旧结果不可直接比较**。保持 forward=20 则经济含义不变，
只是采样更密——严格更优。

### 重算结果（已落库）

新增 `scripts/recalc_factors.py`，对存量 35 个不同表达式按新口径重算，
**追加新记录而非覆盖**（挖掘流水 append-only，保留可追溯；
`result_json` 内写 `recalc_tag=recalc_20261008` 标记）。

抽样验证（新旧对照）：

| 因子 | 旧 IC | 新 IC | 旧评级 | 新评级 |
|---|---|---|---|---|
| 估值-动量复合 | +0.0560 | +0.0559 | 弱 | **可用** |
| GP-1 | −0.0376 | **−0.0589** | **可用**（误判） | **反向** ✅ |
| GP-2 | −0.0212 | −0.0498 | 弱 | **反向** |

`GP-1` 是典型案例：旧口径 IC 更小却被判「可用」，新口径下IC 更负、
**评级正确地变为「反向」**。这印证了 B1+B2 修复的方向性——

- B1（估值 PIT）：修正了**输入数据的时点**
- B2（周频）：修正了**检验功效**
- M1-2（`has_pos`）：修正了**评级方向**

三者叠加，因子评级才真正可信。
