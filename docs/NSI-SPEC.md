## 1. 系统定位与边界

### 1.1 一句话定义

用宽基 ETF 份额的日频变化，测量「有组织承接资金」的介入强度，输出一个 **0–100 的信号分**，用于**在基础仓位上做加法**。

### 1.2 做什么

| # | 能力 | 输出 |
|---|---|---|
| 1 | 每日测量国家队介入强度 | `score`（0–100，可低于 0） |
| 2 | 触发式仓位建议 | `position`（0.70 / 1.00 两档） |
| 3 | 状态与归因说明 | `regime`、`pos_penalty`、分项 `FLOW/PRESS/p750` |

### 1.3 不做什么（防需求蔓延，逐条注明代价）

| 不做 | 原因 | 违反的代价 |
|---|---|---|
| **不预测股价** | 信号只衡量「托底强度」，对后续收益的解释力 IC≈0.03–0.07 | 被要求「给个方向」时会硬答，产生无依据的判断 |
| **不做减仓信号** | 躲跌端实测 −2.42pp（换手 202 次成本吃光） | 加进减仓逻辑，alpha 立刻被交易成本抵消 |
| **不给绝对仓位** | 只能给「基础仓位 → 加仓」的乘数关系 | 给绝对仓位等于替用户做资产配置决策，且回撤不可控 |
| **不确认买家身份** | 份额跳升可能是保险/理财，无法证实是汇金 | 把「大机构」说成「国家队」，归因错误且无法证伪 |
| **不做盘中实时** | 份额 T 日盘后才可得，物理上做不到 | 承诺实时会诱导使用成交量替代，而量能法已证伪（§9.3） |

### 1.4 与 GJI 的分工（避免重复建设）

GJI（护盘强度指标，7 只 ETF 成交量口径）与本系统**不是替代关系**：

| 维度 | GJI | NSI（本系统） |
|---|---|---|
| 数据 | ETF 成交量（二级市场） | ETF 份额（一级申赎） |
| 时效 | T 日收盘即时 | T+1 盘前 |
| 尺度 | 60 日为主 | 20 日为主 |
| 映射 | 连续（50%+10×S） | 二元（70%→100%） |
| 覆盖 | 强：盘中放量 | 强：细水长流低吸 |
| 盲区 | 2024.5–9 低吸期看不见 | 盘中痕迹看不见 |

**结论：两者并存，取长补短。本系统不重复实现量能逻辑。**

### 2.4 口径纪律（五条，违反即结论作废）

| # | 规则 | 违反后果 |
|---|---|---|
| 1 | `fd_share` 单位是**万份**，不可与 `vol`（手）混用 | 量级错 10⁴，分位全乱 |
| 2 | ETF 份额**不做复权**（份额本身无复权概念） | 引入不存在的调整 |
| 3 | 信号 T 日产生、**T+1 开盘执行**，不得用 T 日收盘价成交 | 引入前视，实测虚增 0.14pp |
| 4 | 所有分位用**滚动窗口**（250/750 日），禁止全样本分位 | 前视，回测收益虚高 |
| 5 | **禁止对最终信号再做滚动分位化** | 夏普 0.38 → 0.02，信号被毁（§9.3） |

### 2.5 缺失与异常处理

| 情况 | 处理 |
|---|---|
| 单只 ETF 当日无数据 | 该只从当日篮子中剔除，其余取均值；有效只数 <3 则该日 `FLOW=NaN` |
| 指数停牌/无数据 | 前向填充最多 3 个交易日，超过则标记该日信号无效 |
| 分钟数据缺失 | `B2` 置 NaN，`FLOW` 用剩余 4 项；若连续缺失 >5 日则告警 |
| `fd_share` 出现 0 或负值 | 视为脏数据置 NaN，不参与计算 |
| 全流程任一环节失败 | 保留上一日 `nsi_latest.json`，`as_of` 不变，写告警日志 |

## 3. 指标定义

### 3.1 原子指标

所有 `n01(x)` 表示 **x 在滚动 250 日窗口内的百分位**（`min_periods=80`），实现见 §9.4 参考实现。

| 代号 | 含义 | 公式 | 窗口 |
|---|---|---|---|
| `A1` | 份额日脉冲（去趋势） | `mean_i( ΔS_i − median60(ΔS_i) )`，`ΔS_i = S_i.pct_change()` | 60 日去趋势 |
| `A2` | 份额 5 日动量（去趋势） | `mean_i( m5_i − median60(m5_i) )`，`m5_i = S_i.pct_change(5)` | 60 日去趋势 |
| `A3` | 份额广度 | `count(ΔS_i>0) / count(ΔS_i 有效)` | 当日 |
| `A4` | 净流入占存量比 | `Σ(ΔS_i) / Σ(S_i) × 100` | 当日 |
| `C3` | 份额 20 日动量（去趋势） | `mean_i( m20_i − median60(m20_i) )` | 60 日去趋势 |
| `B1` | 收盘日内位置 | `(close − low) / (high − low)` | 当日 |
| `B2` | 尾盘 30min 强度 | `(close15:00 / close14:30 − 1)×100 − pct_chg` | 当日 |
| `B3` | 大小盘风格差 | `pct_chg(sz50) − pct_chg(zz1000)` | 当日 |
| `B4` | 银行超额 | `pct_chg(bank) − pct_chg(hs300)` | 当日 |
| `B5` | 上影线（取负） | `−(high − close)/close × 100` | 当日 |
| `C1` | 市场 20 日动量 | `close.pct_change(20) × 100` | 20 日 |
| `C4` | 市场 20 日波动 | `std(pct_chg, 20)` | 20 日 |

> `S_i` = 第 i 只核心 ETF 的 `fd_share`，`i ∈ CORE`。

### 3.2 三个合成指标

```
FLOW  = mean( n01(A1), n01(A2), n01(A3), n01(A4), n01(C3) )      # 资金痕迹，5 项等权
PRESS = ( n01(−C1) + n01(C4) ) / 2                               # 市场压力
NSI   = FLOW × (0.4 + 0.6 × PRESS) × 100                          # 0–100，理论可达 0
```

**`0.4 + 0.6×PRESS` 的含义**：压力为 0 时，流入只算 4 折（大概率是常规配置）；压力最大时全额计入。
这是「状态依赖」——同样的资金流入，在暴跌期才有托底含义。

### 3.3 位置惩罚（来自 GJI，独立实现）

```
p750  = percentile_rank(close, window=750, min_periods=250)      # 0–1

pos_pen =  −3.0   若 p750 ≥ 0.90
           −2.0   若 0.80 ≤ p750 < 0.90
           −1.0   若 0.65 ≤ p750 < 0.80
           +0.5   若 p750 ≤ 0.15
            0.0   其他

score = NSI + pos_pen × 4
```

**这段是全系统最反直觉、也最值钱的设计。** 它的作用是压掉「牛市高位放量」的误判：

| 日期 | 沪深300 | NSI | p750 | pos_pen | score | 实际后续 |
|---|---|---|---|---|---|---|
| 2021-02-10 | 5808（历史顶部） | 22.65 | 1.00 | −3.0 | **10.65** | 随后大跌 |
| 2026-06-30 | 5060（阶段顶部） | 21.12 | 1.00 | −3.0 | **9.12** | 下半年 −21% |
| 2024-02-05 | 3180（历史底部） | 84.19 | 0.00 | +0.5 | 86.19 | 随后反弹 |

**没有这一层，2021 和 2026 两个顶部 NSI 本身并不高、拦不住；加上之后 score 被压到 10 以下，明确不放行加仓。**

> ⚠️ **实现陷阱**：`pos_pen` 必须加在 `NSI` 原始刻度上，**绝不可以先对 NSI 做滚动分位再加**。
> 这个错误在研究中犯了两次，每次都把年化虚增 1.8pp 或把夏普打到 0.02。

### 3.4 计算顺序（严格按此顺序，不得重排）

```python
1. 载入 5 只指数日线 + 5 只 ETF 份额 + 30min 分钟数据
2. 以 hs300 交易日为基准日历，其余数据 reindex + ffill(limit=3)
3. 计算 A1..A4, B1..B5, C1, C3, C4（全部只用当日及历史数据）
4. 计算 FLOW / PRESS（滚动 250 日分位）
5. 计算 NSI = FLOW × (0.4 + 0.6×PRESS) × 100
6. 计算 p750 与 pos_pen
7. 计算 score = NSI + pos_pen × 4
8. 按 §4 状态机生成 position
```

### 3.5 样本与预热

- 最早可用日期：**2018-06-01**（需 250 日预热 + 至少 80 个有效点）
- `p750` 需 250 个点，最早 **2019-01 前后**才有效
- 2024-06-01 之前建议标注 `backtest_only=true`，不作为实盘依据

## 4. 信号与仓位

### 4.1 参数表（全部来自训练期，禁止手工调优）

| 参数 | 值 | 来源 | 可调范围 |
|---|---|---|---|
| `TRAIN_END` | `2023-12-31` | 训练/验证切分点 | 不可调 |
| `HI_QUANTILE` | `0.97` | 训练期 score 的 97 分位 | 0.95–0.99（>90 分位失效） |
| `HOLD_DAYS` | `20` | 交易日 | 10–60 |
| `BASE_POS` | `0.70` | 用户基础仓位 | 0.30–0.90 |
| `BOOST_POS` | `1.00` | 加仓上限 | ≥ BASE_POS |
| `POS_PEN_W` | `4.0` | 位置惩罚权重 | 4–6（8 以上过度压制） |

**阈值必须在运行时由训练期分位算出，不得写死数值**（当前训练期 97 分位 = **71.34**，数据更新后会变化）：

```python
hi_threshold = score[score.index <= "2023-12-31"].quantile(0.97)
```

### 4.2 状态机

```
状态：BASE（基础仓位 0.70） / BOOST（加仓 1.00）

初始化：position = BASE，last_trigger = −∞

每日 t：
    if score[t] >= hi_threshold:
        last_trigger = t
    if (t − last_trigger) <= HOLD_DAYS:
        position = BOOST
    else:
        position = BASE
```

**注意：这是单向状态机，`score` 低不会触发减仓。** 只在 `HOLD_DAYS` 到期后自然回落。

### 4.3 边界条件（必须显式处理）

| 情况 | 行为 |
|---|---|
| 首次运行，无历史 | `position = BASE`，`last_change = null` |
| `score` 为 NaN | 沿用上一日 `position`，不重算 `last_trigger` |
| 连续多日超阈值 | `last_trigger` 每日刷新，`HOLD_DAYS` 从最后一次触发重新计时 |
| 单日 NaN 后恢复 | 正常计分；若 NaN 期间跨越了 `HOLD_DAYS` 边界，按「未触发」处理 |
| `score` 恰等于阈值 | 视为触发（`>=`，不是 `>`） |
| 假期/非交易日 | 不产生新信号，沿用上一交易日 |

### 4.4 仓位落地（给用户的话术模板）

```
当前 score = {score}，阈值 {hi_threshold}
→ 你的基础仓位 {BASE_POS}，本日建议 {position}

若 score 由高位快速回落至阈值以下且仍处于 HOLD_DAYS 内：
「信号已转弱，但按规则仍在加仓窗口，{剩余天数} 个交易日后回落」
```

## 6. 运行规格

### 6.1 执行方式

```bash
# 增量更新（日常）
docker exec -e QUANT_TUSHARE_TOKEN=xxx quant-backend \
  python /data/research/nsi_daily.py

# 全量重建（首次部署 / 换年后 / 数据异常）
docker exec -e QUANT_TUSHARE_TOKEN=xxx quant-backend \
  python /data/research/nsi_daily.py --full

# 回归复核（改代码后必跑）
docker exec -e QUANT_TUSHARE_TOKEN=xxx quant-backend \
  python /data/research/nsi_daily.py --backtest
```

### 6.2 调度

| 时点 | 动作 | 理由 |
|---|---|---|
| 每交易日 19:30 | 增量更新 | ETF 份额 T 日盘后可得；晚于 19:00 ETL 避免资源竞争 |
| 每周末 | 全量重建 + 回归 | 检查分页漏拉、阈值漂移 |
| 每季度末 | 复核阈值与位置惩罚分档 | 训练期数据增长，阈值会缓慢移动 |

**不建议盘中运行**：份额数据盘中不存在，跑了也是旧值。

### 6.3 失败处理

| 失败点 | 处理 | 告警 |
|---|---|---|
| tushare 请求失败 | 重试 3 次（间隔 1.5/3/4.5s），仍失败则中止 | 是 |
| 增量更新后无新数据 | 正常退出，`as_of` 不变 | 否 |
| 有效性检查失败（§7） | 中止，不写 `nsi_latest.json` | **是，最高优先级** |
| `as_of` 落后 >3 交易日 | 写告警字段 | 是 |

### 6.4 日志

每次运行输出单行摘要，格式固定：

```
[NSI] {as_of}  score={score}（NSI {nsi_raw} + 位置惩罚 {pos_pen:+.1f}×4）
[NSI] 阈值={hi}  仓位={position}  {regime}
[NSI] 加仓已持续 {holding_days} 个交易日，上限 20 日
```

**执行口径（与策略 PIT 对齐）**

```
T 日收盘 → T+1 日 08:30 调度器刷新（此时 T 日份额已完整）
        → T+1 日 09:30 开盘，策略读 T 日信号建仓
```

**⚠️ 调度时点为什么不是当晚 19:30**

2026-11-03 实测：ETF 份额并非「T 日盘后立刻可得」。前一晚 22:30 运行，
11-02 份额尚未落地，增量更新只拿到指数数据，ffill 使 `A1`(日脉冲)=0，
算出 score=**48.9**；次日 08:57 份额补齐后同样是 11-02，score=**77.3**。
**差近一倍。** 当晚跑等于系统性低估托底强度，故改到次日早上。

脚本已内置 `data_lag_days` 检测，份额落后时会在 `nsi_latest.json` 的
`data_warning` 字段和运行日志里显式告警。

**平台侧的两个缺陷（本策略接入时修复）**

| 缺陷 | 现象 | 修复 |
|---|---|---|
| 单标的回测只读个股表 | `sh000300` 报「未获取到行情」 | `_run_single` 查不到个股时回退 `_load_index_bars` |
| 指数按 100 股/手取整 | 沪深300≈3000 点，一手 30 万，100 万本金仓位精度只剩 30%，只成交 2 笔 | `sh000*`/`sz399*` 改用 `lot_size=1` |

修复后同区间（2019-01-01~2026-11-02，10bp 成本）：年化 3.91%、回撤 −38.18%、
夏普 0.16、成交 28 笔。对照基准总收益 33.50% vs 沪深300 35.27% ——
**绝对收益略跑输基准 1.77pp，因为平均仓位只有约 75%**；按仓位折算是跑赢的，
但不得对外表述为「策略跑赢指数」。

**代码热挂载**

`docker-compose.yml` 增加 `./backend/app:/app/app`，改策略代码重启容器即生效，
不必 `docker compose build`。代价是没有 review 环节、语法错误会让容器起不来
（改回宿主机文件即可恢复）。

|---|---|---|

## 8. 已知局限与失效监控

### 8.1 统计功效（不可回避）

- 独立事件约 **8–10 轮**（2018Q4、2020、2022 两次、2024Q1、2025Q1、2026 两次）
- **能可靠否定「极强有效」，不能断定「无效」**——这两句话必须同时出现在任何结论里
- S≥3.5 桶仅 13 个样本、胜率 100%，**高度可疑，不得作为加仓理由**

### 8.2 Regime 依赖

样本期 2018-2026 是 A 股长熊（满仓 8 年年化 −0.25%）。在这种样本里，任何「少参与」的设计天然占优。
**牛市年超额 +2.43pp 是本方案唯一的抗争议证据**，但仍需 2027 年后持续验证。

### 8.3 归因不确定（永久性）

份额跳升 ≠ 汇金。可能来源：保险/理财逆势配置、做市商套利、分红再投资。
**已知无法用现有数据证伪**，只能用「公告」做置信度加权（近 60 交易日有公告 = 高置信）。

### 8.4 失效监控（上线后必须持续看）

| 监控项 | 阈值 | 触发后动作 |
|---|---|---|
| `score` 连续 250 日不触发 | 信号沉默 | 复核阈值是否过高、市场结构是否变化 |
| 触发后 20 日均值收益 | 连续 3 次为负 | 暂停使用，重跑回测 |
| 份额数据披露延迟 | >1 个交易日 | 检查数据源，必要时改用 T+2 执行 |
| `p750` 与指数实际位置背离 | 分档错位 | 检查复权与窗口设置 |

## 9. 附录

### 9.1 研究结论摘要

**机制**：国家队目标函数不是收益最大化，而是防系统性风险 → 在恐慌期提供价格不敏感的承接 → 该承接在宽基 ETF 一级申赎上留下日频痕迹 → 可观测、可跟随。

**关键转折**（本研究的核心发现）：
收益来源分解显示 **抄底端 +0.49pp（换手 21）** 而 **躲跌端 −2.42pp（换手 202）**。
据此把系统形态从「择时加减仓」改为「只做加法」，牛市年从跑输 13.8pp 反转为跑赢。

### 9.2 参数来源

> 本节与 §9.3 的收益数字均为**研究口径**（A4 用金额加权，年化 1.99%），
> 与生产实现（A4 份额加权，年化 1.52%）存在约 0.5pp 差异。
> **结论方向不受影响**（同样是正超额、低换手），但具体数值不可混用。

| 参数 | 怎么来的 |
|---|---|
| `HI_QUANTILE=0.97` | 阈值稳健性扫描 90/95/97/98/99 分位，90 分位失效（换手 97、年化 0.50%），95–99 稳定（2.46–2.80%），97 分位实测最优 |
| `HOLD_DAYS=20` | 5/10/20/40/60 扫描，20 日最优（+1.18pp），60 日次之 |
| `POS_PEN_W=4` | 4/6/8 扫描，4 最优（1.99%），8 过度压制（1.92%） |
| 位置惩罚分档 | 直接沿用 GJI 文档 §3（90/80/65/15%），未做调优 |

### 9.3 反面清单（**不要重走的路，每条都实测过**）

| 错误做法 | 实测后果 |
|---|---|
| 对最终信号做滚动分位化 | 夏普 0.38 → **0.02**，绝对流入强度是信息本体 |
| 位置惩罚先滚动分位再加 | 年化虚增到 3.79%（假象），真实 1.99% |
| 用 ETF 成交量替代份额 | IC 训练 **−0.19** / 验证 **+0.13**，方向整个翻转 |
| 连续映射仓位（50%+10×S） | 换手 **116 次**、年化 1.44%，远逊二元加法的 8.7 次 / 1.99% |
| 连续映射 + 减仓 | 换手 202 次，贡献 −2.42pp |
| 五档连续调仓（20/40/60/80/100%） | 换手 247 次，扣 10bp 后 alpha 归零 |
| 用价格行为指标找国家队 | 尾盘强度 IC=0.008、收盘位置 IC=0.010、银行超额方向翻 |
| 做「无公告封顶 +3」 | 年化 1.99% → 1.82%，降收益换降回撤，性价比不过关 |
| 硬过滤 p750<0.65 | 年化 1.74%，劣于加分式 1.99% |
| 直接连 SQLite 写 | 与容器 WAL 冲突，后端 `disk I/O error`，需 `docker restart` |

### 9.6 开工前必读的三条

1. **不要重写指标公式**。§3 的公式每一个都经过回测验证，看起来「可以简化」的地方（比如去掉 60 日去趋势、把 5 项等权改成按 IC 加权）都试过，全部变差。
2. **不要对 `score` 再做任何归一化**。这是本系统最容易犯的错，已犯两次，每次损失 0.15–1.8pp 年化。
3. **不要为了「覆盖更多情况」加指标**。13 个原子指标的 IC 全部 < 0.08，价值来自合成降噪，不来自单个指标。加第 14 个之前先跑 §7.3 的验收门槛。
